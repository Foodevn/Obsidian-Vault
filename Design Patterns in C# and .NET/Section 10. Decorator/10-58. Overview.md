## Mẫu thiết kế Trang trí (Decorator Design Pattern)

### Khái niệm
- Mẫu thiết kế Trang trí (Decorator Design Pattern) cho phép thêm hành vi (behavior) vào các lớp hiện có mà không cần thay đổi mã nguồn của chúng.
- Mục tiêu: Bổ sung chức năng mới cho đối tượng một cách linh hoạt, tuân thủ các nguyên tắc thiết kế như **Nguyên tắc Mở/Đóng (Open/Closed Principle)** và **Nguyên tắc Trách nhiệm Đơn lẻ (Single Responsibility Principle)**.

### Động lực sử dụng
- **Mục đích**:
  - Bổ sung chức năng mới cho đối tượng mà không sửa đổi mã nguồn hiện có.
  - Tránh thay đổi mã đã được kiểm thử và đang hoạt động, giảm nguy cơ gây lỗi.
  - Giữ các chức năng mới tách biệt, đảm bảo mỗi lớp chỉ chịu trách nhiệm cho một chức năng cụ thể.
- **Vấn đề**:
  - Việc sửa đổi mã nguồn đã hoàn thiện có thể gây ra lỗi không mong muốn, ngay cả khi có kiểm thử đầy đủ.
  - Cần duy trì khả năng tương tác với các cấu trúc hiện có.

### Cách hoạt động
- Mẫu Trang trí hoạt động bằng cách:
  - **Tham chiếu (Reference)** đến đối tượng cần trang trí.
  - Cung cấp hành vi bổ sung trên đối tượng gốc mà không cần sửa đổi nó.
- Có hai cách tiếp cận chính:
  1. **Kế thừa (Inheritance)**:
     - Nếu lớp không bị khóa (sealed), có thể kế thừa từ lớp gốc để thêm hành vi mới.
     - Lợi ích: Kế thừa toàn bộ đặc điểm của lớp gốc và bổ sung hành vi mới dễ dàng.
     - Hạn chế: Không khả thi nếu lớp bị khóa (ví dụ: lớp `StringBuilder` trong một số ngôn ngữ).
  2. **Tổng hợp (Aggregation)**:
     - Nếu lớp bị khóa, sử dụng một đối tượng Trang trí (Decorator) để tham chiếu đến đối tượng gốc.
     - Sao chép (replicate) API của đối tượng gốc và chuyển tiếp (proxy) các cuộc gọi đến nó.
     - Thêm hành vi mới trên lớp Trang trí.

### Ví dụ minh họa
- Giả sử có một lớp `StringBuilder` (bị khóa, không thể kế thừa):
  - Tạo một lớp Trang trí tham chiếu đến `StringBuilder`.
  - Sao chép các phương thức cần thiết của `StringBuilder` (ví dụ: `Append`, `ToString`).
  - Thêm hành vi mới, ví dụ: tự động thêm ký tự đặc biệt vào chuỗi.
- Cụ thể:
  - Đối tượng gốc: `StringBuilder` với các phương thức cơ bản.
  - Đối tượng Trang trí: Thêm chức năng như tự động thêm dấu cách hoặc ký tự đặc biệt sau mỗi chuỗi.

### Mã nguồn ví dụ
```csharp
// Lớp gốc (giả định bị khóa)
public sealed class StringBuilder
{
    public string Append(string value) => value;
    public string ToString() => value;
}

// Lớp Trang trí
public class StringBuilderDecorator
{
    private readonly StringBuilder _stringBuilder;

    public StringBuilderDecorator(StringBuilder stringBuilder)
    {
        _stringBuilder = stringBuilder;
    }

    // Sao chép và chuyển tiếp API
    public string Append(string value)
    {
        // Thêm hành vi mới
        string decoratedValue = value + "!";
        return _stringBuilder.Append(decoratedValue);
    }

    public string ToString() => _stringBuilder.ToString();
}
```

### Lợi ích
- **Tuân thủ Nguyên tắc Mở/Đóng**: Mở rộng chức năng mà không sửa đổi mã gốc.
- **Tách biệt trách nhiệm**: Chức năng mới được giữ trong lớp Trang trí riêng biệt.
- **Linh hoạt**: Có thể áp dụng cho các lớp bị khóa hoặc không bị khóa.

### Hạn chế
- Khi sử dụng tổng hợp, cần sao chép API của lớp gốc, có thể tốn công sức.
- Yêu cầu công cụ hỗ trợ (như ReSharper) để tự động hóa việc sao chép và chuyển tiếp API.
