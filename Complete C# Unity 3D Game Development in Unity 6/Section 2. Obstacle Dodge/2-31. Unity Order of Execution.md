## Sửa lỗi khởi tạo Projectile và Thứ tự Thực thi trong Unity

## Khái niệm cơ bản

- Unity cung cấp nhiều hàm gọi lại (event functions) theo một **thứ tự thực thi (Execution Order)** cố định, ví dụ: `Awake` → `OnEnable` → `Start` → `FixedUpdate` → `Update` → `LateUpdate` → các callback vật lý/va chạm → …
- `Awake` được gọi đầu tiên ngay khi GameObject “đánh thức” (không phụ thuộc trạng thái active).
- `Start` chỉ được gọi khi component và GameObject đã active.

## Vấn đề ban đầu

- Các **projectiles** (đạn) được thiết lập thủ công ở trạng thái active để có thể di chuyển và chỉnh sửa trong Scene.
- Quên tắt active trước khi chạy → va chạm với Trigger Volume gây lỗi:

  ```text
   NullReferenceException: Trying to set active on a destroyed GameObject
   ```

- Lỗi xuất phát từ script `FlyAtPlayer` ở đoạn:

    ```csharp
    void Start() {     
	    GameObject.SetActive(false);     // Lưu vị trí player để về sau fly tới 
    } 
    void Update() {     
	    if (reachedPlayer) {         
		    Destroy(gameObject);     
		} 
	}
    ```
    
    Vòng đời:
    1. `Start` tắt GameObject ngay đầu → không kích hoạt lại khi cần.
    2. Script vẫn gọi `Destroy(gameObject)` → sau đó nếu cố bật lại thì null reference.

## Giải pháp: Đưa lệnh tắt active vào `Awake`

- Thay vì tắt trong `Start`, đặt lệnh tắt active ngay trong `Awake` để:
    - Đảm bảo projectile luôn inactive trước mọi logic khởi tạo khác.
    - Không ảnh hưởng đến phép tính lưu vị trí player trong `Start`.


```csharp
public class FlyAtPlayer : MonoBehaviour {     
	void Awake() {         
		gameObject.SetActive(false);     
	} 
	
	void Start() {         
		// Lưu vị trí player để fly tới         
		playerPosition = GameObject.FindWithTag("Player").transform.position;     
	}  
	   
	void Update() {         
		// Di chuyển về hướng playerPosition         
		// Khi đến nơi thì Destroy(gameObject);     
	} 
}
```

## Thứ tự Thực thi (Execution Order) trong Unity

- Unity gọi các hàm event functions theo trình tự sau (khái quát):

    1. **Initialization Phase**
        - `Awake()`
        - `OnEnable()`
    2. **First Frame Phase**
        - `Start()`
    3. **Update Loop**
        - `FixedUpdate()` (Physics)
        - `Update()` (Game logic)
        - `LateUpdate()` (Sau Update)
    4. **Rendering**
        - Vẽ Scene và Gizmos
    5. **Destruction Phase**
        - `OnDisable()`
        - `OnDestroy()`

- Một số callback khác:
    - `Reset()`, `OnValidate()` (chỉ Editor)
    - `OnTriggerEnter()`, `OnCollisionEnter()` (vật lý/va chạm)

## Lưu ý khi áp dụng

- Dùng `Awake` để khởi tạo hoặc tắt/mở GameObject, gán biến tham chiếu không phụ thuộc trạng thái active.
- Dùng `Start` để thực hiện các logic khi GameObject đã active, như tính toán vị trí, thiết lập trạng thái ban đầu.
- Tránh đặt logic vật lý vào `Update`; dùng `FixedUpdate` cho physics.
