# Ghi chú học tập: Nguyên tắc định dạng C# trong Unity

## Tổng quan
- **Mục tiêu**:
  - Hiểu các nguyên tắc định dạng cơ bản trong C# khi lập trình trong Unity.
  - Làm quen với các khái niệm như **bình luận (comments)**, **khoảng trắng (white space)**, **dấu ngoặc nhọn (curly braces)**, và **lớp (class)**.
  - Hiểu phạm vi (scope) của biến và cách các hàm như `Update()` truy cập chúng.
- **Dự án**: Obstacle Dodge
- **Gợi ý liên kết**: [[C# Formatting]], [[Code Structure]], [[Obstacle Dodge]]

## Nội dung chi tiết

### 1. Bình luận (Comments)
- **Mô tả**:
  - Bình luận là ghi chú trong mã, được Unity và trình biên dịch bỏ qua.
  - Dùng để giải thích mã, ghi chú ý định, hoặc nhắc nhở cho sau này.
- **Cú pháp**:
  - Sử dụng `//` (double forward slash) để tạo bình luận một dòng.
    ```csharp:disable-run
    // Đây là bình luận, Unity sẽ bỏ qua
    ```
- **Ví dụ**:
  - Unity tự động thêm bình luận cho `Start()` và `Update()` trong script mới:
    ```csharp
    // Start is called before the first frame update
    void Start()
    {
    }
    ```
  - Có thể xóa bình luận mặc định để làm gọn mã.
- **Lý do sử dụng**:
  - Giúp hiểu mã khi quay lại sau thời gian dài (ví dụ: 6 tháng).
  - Hữu ích cho người mới, khi mã chưa được tối ưu hoặc đặt tên rõ ràng.
- **Lưu ý**:
  - Một số lập trình viên cho rằng mã nên tự giải thích (qua tên biến/hàm rõ ràng) để không cần bình luận.
  - Tuy nhiên, bình luận rất hữu ích khi học hoặc làm việc nhóm.
- **Gợi ý liên kết**: [[Code Comments]], [[Code Readability]]

### 2. Khoảng trắng (White Space)
- **Mô tả**:
  - Khoảng trắng (spaces, tabs, dòng trống) không ảnh hưởng đến cách mã chạy trong C#.
  - Được sử dụng để tăng tính dễ đọc và tổ chức mã.
- **Ví dụ**:
  - Biến khai báo với khoảng trắng linh hoạt:
    ```csharp
    [SerializeField]     float    xValue    =    0f; // Hợp lệ
    ```
  - Nhưng không được phá vỡ từ khóa hoặc tên biến:
    ```csharp
    floatxValue = 0f; // Sai, gây lỗi
    float xValue = 0f; // Đúng
    ```
- **Lưu ý**:
  - Nếu xuất hiện **gạch đỏ (red squiggly lines)** trong Visual Studio Code, kiểm tra khoảng trắng hoặc cú pháp sai.
  - Sử dụng khoảng trắng hợp lý để mã dễ đọc, đặc biệt khi làm việc nhóm.
- **Gợi ý liên kết**: [[White Space in Code]], [[C# Syntax]]

### 3. Dấu ngoặc nhọn (Curly Braces) và Code Block
- **Mô tả**:
  - Dấu ngoặc nhọn `{}` xác định **code block**, tức là phạm vi của một hàm hoặc lớp.
  - Mọi thứ trong `{}` được thực thi khi hàm hoặc lớp được gọi.
- **Ví dụ**:
  - Trong hàm `Update()`:
    ```csharp
    void Update()
    {
        transform.Translate(xValue, yValue, zValue); // Code block
    }
    ```
    - Code trong `{}` chạy mỗi khung hình.
  - Trong lớp (class) `Mover`:
    ```csharp
    public class Mover : MonoBehaviour
    {
        // Tất cả biến, hàm trong này thuộc về lớp Mover
    }
    ```
    - Toàn bộ nội dung script nằm trong `{}` của lớp.
- **Phong cách định dạng**:
  - Cách 1 (phổ biến): Dấu `{` trên dòng riêng:
    ```csharp
    void Update()
    {
    }
    ```
  - Cách 2: Dấu `{` cùng dòng với tên hàm:
    ```csharp
    void Update() {
    }
    ```
  - Cả hai cách đều hợp lệ, nhưng cách 1 phổ biến hơn vì dễ đọc.
- **Lưu ý**:
  - Thụt lề (indentation) mỗi code block giúp mã dễ đọc:
    ```csharp
    void Update()
    {
        if (condition)
        {
            // Thụt lề thêm cho code block lồng nhau
        }
    }
    ```
  - Thụt lề không ảnh hưởng mã, nhưng là chuẩn mực trong lập trình để tránh nhầm lẫn.
- **Gợi ý liên kết**: [[Code Blocks]], [[Indentation]]

### 4. Phạm vi (Scope) của biến
- **Mô tả**:
  - Biến khai báo ngoài `Start()` và `Update()` (trong lớp) có phạm vi **toàn cục (class scope)**, được cả hai hàm truy cập.
  - Biến trong một code block (giữa `{}`) chỉ tồn tại trong block đó.
- **Ví dụ**:
  - Biến toàn cục:
    ```csharp
    [SerializeField] float xValue = 0f;
    void Update()
    {
        transform.Translate(xValue, 0f, 0f); // xValue có thể truy cập
    }
    ```
  - Nếu khai báo biến trong `Start()`:
    ```csharp
    void Start()
    {
        float tempValue = 0.1f; // Chỉ tồn tại trong Start
    }
    void Update()
    {
        // Update không biết tempValue, gây lỗi nếu sử dụng
    }
    ```
- **Ứng dụng**:
  - Trong dự án Obstacle Dodge, biến `xValue`, `yValue`, `zValue` được khai báo ở đầu lớp để `Update()` sử dụng.
  - Điều này cho phép thay đổi giá trị trong **Inspector** hoặc mã, và `Update()` luôn truy cập giá trị mới nhất.
- **Vấn đề**:
  - `Update()` không tự biết về thay đổi từ input (như bàn phím/controller) trừ khi được lập trình để cập nhật biến.
  - Sẽ được giải quyết trong bài giảng sau bằng cách thêm input xử lý.
- **Gợi ý liên kết**: [[Variable Scope]], [[Player Input]]

## Ghi chú thêm
- **Lời khuyên**:
  - Thêm bình luận để ghi chú ý định, đặc biệt khi mới học, nhưng cố gắng đặt tên biến/hàm rõ ràng để giảm phụ thuộc vào bình luận.
  - Sử dụng thụt lề và khoảng trắng nhất quán để mã dễ đọc, đặc biệt khi làm việc nhóm hoặc xin việc.
  - Hiểu phạm vi của biến để tránh lỗi khi hàm không truy cập được giá trị cần thiết.
  - Thử nghiệm thêm bình luận hoặc thay đổi định dạng (như vị trí dấu `{}`) để làm quen, nhưng giữ chuẩn mực khi làm việc chuyên nghiệp.
