# Ghi chú học tập: Tạo hình ảnh Docker tùy chỉnh

## Tạo hình ảnh Docker tùy chỉnh

### Mục tiêu
- Hiểu cách tạo hình ảnh Docker (Docker image) tùy chỉnh cho ứng dụng.
- Áp dụng các bước để xây dựng, đẩy và quản lý hình ảnh Docker.
- Tập trung vào việc đóng gói (containerize) một ứng dụng web đơn giản sử dụng khung Python Flask (Python Flask framework).

### Lý do cần tạo hình ảnh Docker tùy chỉnh
- Không tìm thấy thành phần/dịch vụ cần thiết trên [[Docker Hub]].
- Ứng dụng cần được đóng gói để dễ dàng vận chuyển (shipping) và triển khai (deployment).

### Quy trình tạo hình ảnh Docker
#### 1. Hiểu ứng dụng cần đóng gói
- Xác định ứng dụng và cách nó được xây dựng.
- Các bước triển khai thủ công:
  - Cài đặt hệ điều hành, ví dụ: Ubuntu.
  - Cập nhật kho lưu trữ nguồn bằng lệnh `apt`.
  - Cài đặt các phụ thuộc hệ thống bằng `apt`.
  - Cài đặt các phụ thuộc Python bằng `pip`.
  - Sao chép mã nguồn ứng dụng vào vị trí, ví dụ: `/opt`.
  - Chạy máy chủ web bằng lệnh Flask.

#### 2. Tạo tệp Dockerfile
- **Định nghĩa**: Tệp văn bản chứa các hướng dẫn để Docker xây dựng hình ảnh, được đặt tên là `Dockerfile`.
- **Cấu trúc**: Bao gồm **hướng dẫn** (in hoa, ví dụ: `FROM`, `RUN`, `COPY`, `ENTRYPOINT`) và **đối số**.
- **Nội dung chính của Dockerfile**:
  - `FROM`: Chỉ định hình ảnh cơ sở (base image), ví dụ: `FROM ubuntu`.
    - Mọi hình ảnh Docker phải dựa trên một hình ảnh cơ sở (hệ điều hành hoặc hình ảnh khác).
    - Các hình ảnh cơ sở chính thức có sẵn trên [[Docker Hub]].
  - `RUN`: Thực thi lệnh trong quá trình xây dựng hình ảnh.
    - Ví dụ: `RUN apt-get update` để cập nhật gói phần mềm.
    - Cài đặt các phụ thuộc hệ thống và Python.
  - `COPY`: Sao chép tệp từ hệ thống cục bộ vào hình ảnh Docker.
    - Ví dụ: Sao chép mã nguồn từ thư mục hiện tại vào `/opt` trong hình ảnh.
  - `ENTRYPOINT`: Chỉ định lệnh được thực thi khi vùng chứa (container) khởi động.
    - Ví dụ: Chạy ứng dụng Flask.

#### 3. Xây dựng hình ảnh
- Sử dụng lệnh:
  ```bash
  docker build -t <tên_tài_khoản>/<tên_hình_ảnh> .
  ```
- Kết quả: Tạo hình ảnh cục bộ trên hệ thống.
- **Kiến trúc phân lớp (layered architecture)**:
  - Mỗi hướng dẫn trong Dockerfile tạo một lớp (layer) mới.
  - Mỗi lớp chỉ lưu trữ các thay đổi từ lớp trước, giúp tối ưu kích thước hình ảnh.
  - Ví dụ:
    - Lớp 1: Hệ điều hành cơ sở (Ubuntu, ~120MB).
    - Lớp 2: Cài đặt gói `apt` (~300MB).
    - Lớp 3: Cài đặt gói Python.
    - Lớp 4: Sao chép mã nguồn.
    - Lớp 5: Cập nhật điểm vào (entry point).
  - Kiểm tra thông tin lớp bằng lệnh:
    ```bash
    docker history <tên_hình_ảnh>
    ```

#### 4. Đẩy hình ảnh lên Docker Hub
- Sử dụng lệnh:
  ```bash
  docker push <tên_tài_khoản>/<tên_hình_ảnh>
  ```
- Hình ảnh được lưu trữ công khai trên [[Docker Hub]].

### Lợi ích của kiến trúc phân lớp
- **Tối ưu hóa quá trình xây dựng**:
  - Các lớp được lưu vào bộ nhớ cache (cache).
  - Nếu một bước thất bại, Docker sử dụng lại các lớp trước từ cache và tiếp tục từ bước lỗi.
  - Khi thêm hướng dẫn mới hoặc cập nhật mã nguồn, chỉ các lớp liên quan được xây dựng lại.
- **Tiết kiệm thời gian**: Không cần xây dựng lại toàn bộ hình ảnh.
- **Hiệu quả**: Đặc biệt hữu ích khi mã nguồn ứng dụng thay đổi thường xuyên.

### Ví dụ minh họa
- Ứng dụng web Flask:
  ```dockerfile
  FROM ubuntu
  RUN apt-get update && apt-get install -y python3 python3-pip
  RUN pip3 install flask
  COPY . /opt
  ENTRYPOINT ["python3", "/opt/app.py"]
  ```
- **Giải thích**:
  - `FROM ubuntu`: Sử dụng Ubuntu làm hình ảnh cơ sở.
  - `RUN apt-get ...`: Cập nhật và cài đặt Python, pip.
  - `RUN pip3 install flask`: Cài đặt khung Flask.
  - `COPY . /opt`: Sao chép mã nguồn vào `/opt`.
  - `ENTRYPOINT`: Chạy ứng dụng Flask khi vùng chứa khởi động.

### Ghi chú thêm
- Đảm bảo thứ tự các hướng dẫn trong Dockerfile tối ưu để tận dụng bộ nhớ cache.
- Sử dụng [[Docker Hub]] để tìm hình ảnh cơ sở hoặc chia sẻ hình ảnh tùy chỉnh.
- Nếu xây dựng thất bại, kiểm tra thông báo lỗi từ lệnh `docker build` để điều chỉnh Dockerfile.
