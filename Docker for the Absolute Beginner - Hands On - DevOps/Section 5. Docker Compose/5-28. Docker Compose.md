# Ghi chú học tập: Cấu hình Docker Compose và Ứng dụng Mẫu

## Bài giảng: Docker Compose và Ứng dụng Voting Mẫu

### Mục tiêu
- Ôn tập cách chạy container đơn lẻ và giới thiệu Docker Compose (docker-compose) để quản lý ứng dụng đa dịch vụ.
- Hiểu cấu trúc ứng dụng voting mẫu của Docker, bao gồm luồng dữ liệu và các thành phần.
- Học cách triển khai ứng dụng bằng lệnh `docker run` với liên kết (links), sau đó chuyển sang file cấu hình YAML của Docker Compose.
- So sánh các phiên bản Docker Compose (version 1, 2, 3) và cách định nghĩa mạng (networks).

### 1. Ôn tập cơ bản về Docker và Docker Compose
- **Chạy container đơn lẻ**:
  - Sử dụng lệnh `docker run` để khởi động container từ image (ví dụ: `docker run ubuntu`).
  
- **Docker Compose cho ứng dụng phức tạp**:
  - Dùng để quản lý nhiều dịch vụ (services) trên một host Docker duy nhất.
  - Tạo file `docker-compose.yml` để định nghĩa các dịch vụ, tùy chọn (ports, volumes, v.v.).
  - Lệnh `docker compose up` khởi động toàn bộ stack ứng dụng.
  - Ưu điểm: Dễ triển khai, chạy và bảo trì vì tất cả thay đổi lưu trong file YAML.
  - Giới hạn: Chỉ áp dụng cho một host Docker (không dùng cho Swarm hoặc đa host).

- **Lưu ý về YAML**:
  - Sử dụng cú pháp YAML cho file cấu hình. Ôn tập cơ bản YAML trước khi đi sâu (sẽ xem chi tiết sau).

### 2. Giới thiệu ứng dụng Voting Mẫu
- **Mô tả ứng dụng**:
  - Ứng dụng mẫu tiêu chuẩn của Docker để minh họa stack ứng dụng đa thành phần.
  - Gồm hai giao diện: Một cho người dùng vote (chọn giữa mèo và chó), một hiển thị kết quả.
  - Sử dụng đa ngôn ngữ/lập trình: Python, Node.js, .NET, Redis, PostgreSQL.
  - Sẽ sử dụng xuyên suốt khóa học để minh họa các tính năng Docker.

- **Các thành phần và luồng dữ liệu**:
  - **Voting App** (Python web app): Giao diện vote, lưu vote vào Redis (in-memory database).
  - **Worker** (.NET app): Xử lý vote từ Redis, cập nhật số lượng vào PostgreSQL (bảng lưu số vote cho mèo/chó).
  - **Results App** (Node.js web app): Đọc số vote từ PostgreSQL và hiển thị.
  - **Luồng dữ liệu**:
    1. Người dùng vote qua Voting App → Lưu vào Redis.
    2. Worker lấy vote từ Redis → Cập nhật PostgreSQL.
    3. Results App đọc từ PostgreSQL → Hiển thị kết quả.
  - **Kiến trúc**: Kết hợp dịch vụ đa dạng (web, database, worker) để minh họa Docker dễ dàng quản lý stack phức tạp.

### 3. Triển khai bằng lệnh `docker run` (Trên Single Engine)
- **Giả định**: Tất cả image đã build và có sẵn trên Docker Hub (trừ image tùy chỉnh).

- **Bước 1: Khởi động lớp dữ liệu**:
  - Redis: `docker run -d --name redis redis` (chạy nền với `-d`, đặt tên container).
  - PostgreSQL: `docker run -d --name db postgres` (đặt tên để liên kết sau).

- **Bước 2: Khởi động dịch vụ ứng dụng**:
  - Voting App: `docker run -d --name vote -p 5000:80 voting-app` (publish port 80 container sang 5000 host).
  - Results App: `docker run -d --name results -p 5001:80 results-app` (publish port 80 sang 5001 host).
  - Worker: `docker run -d --name worker worker`.

- **Vấn đề**: Các container chạy độc lập, không liên kết (ví dụ: Voting App không biết Redis ở đâu).
  - Lý do: Container không resolve được hostname như "redis" hoặc "db".

- **Giải pháp: Sử dụng `--link` (deprecated)**:
  - Liên kết container để thêm entry vào `/etc/hosts` (IP nội bộ).
  - Ví dụ:
    - Voting App với Redis: `docker run -d --name vote --link redis:redis -p 5000:80 voting-app`.
      - Code Voting App kết nối `redis` (hostname).
    - Results App với DB: `docker run -d --name results --link db:db -p 5001:80 results-app`.
      - Code Results App kết nối `db`.
    - Worker với cả hai: `docker run -d --name worker --link redis:redis --link db:db worker`.
  - **Lưu ý**: `--link` lỗi thời, có thể bị loại bỏ. Sử dụng networking hiện đại (Swarm, networks) thay thế.

### 4. Chuyển sang Docker Compose (File YAML)
- **Tạo file `docker-compose.yml` từ lệnh `docker run`**:
  - Cấu trúc cơ bản (version 1 - trimmed down):
    ```yaml
    vote:
      image: voting-app
      ports:
        - "5000:80"
      links:
        - redis:redis

    results:
      image: results-app
      ports:
        - "5001:80"
      links:
        - db:db

    worker:
      image: worker
      links:
        - redis:redis
        - db:db

    redis:
      image: redis

    db:
      image: postgres
    ```
  - Chạy: `docker compose up` (khởi động toàn bộ stack).

- **Xử lý build image tùy chỉnh**:
  - Nếu image chưa có (ví dụ: voting-app), thay `image` bằng `build`:
    ```yaml
    vote:
      build: ./vote  # Thư mục chứa code và Dockerfile
    ```
  - Khi chạy `docker compose up`, Docker tự build image tạm thời rồi chạy container.

### 5. Các phiên bản Docker Compose File
- **Version 1 (Cũ, hạn chế)**:
  - Định nghĩa trực tiếp dịch vụ ở root level.
  - Không hỗ trợ mạng tùy chỉnh hoặc thứ tự khởi động (depends_on).
  - Tất cả container dùng default bridge network, cần `--link` để giao tiếp.

- **Version 2 (Cải tiến)**:
  - Thêm `version: '2'` ở đầu file.
  - Đóng gói dịch vụ trong section `services`:
    ```yaml
    version: '2'
    services:
      vote:
        image: voting-app
        ports:
          - "5000:80"
        # Không cần links nữa
    ```
  - Tự động tạo bridge network riêng cho stack → Container giao tiếp bằng tên dịch vụ (ví dụ: `redis` resolve tự động).
  - Hỗ trợ `depends_on` cho thứ tự khởi động:
    ```yaml
    vote:
      depends_on:
        - redis  # Redis khởi động trước vote
    ```

- **Version 3 (Mới nhất, hỗ trợ Swarm)**:
  - Thêm `version: '3'` ở đầu.
  - Giống version 2 về cấu trúc (`services`).
  - Hỗ trợ Docker Swarm (deploy stack đa host).
  - Một số tùy chọn thay đổi (xem docs để chi tiết).
  - Sẽ học sâu hơn ở phần Docker Stacks sau.

### 6. Mạng (Networks) trong Docker Compose
- **Mục đích**: Tách biệt traffic (ví dụ: user traffic vs. internal traffic).
  - Frontend network: Cho Voting App và Results App (kết nối user).
  - Backend network: Cho tất cả (Redis, DB, Worker, Voting/Results).

- **Định nghĩa trong file YAML (version 2+)**:
  ```yaml
  version: '2'
  services:
    redis:
      image: redis
      networks:
        - backend

    db:
      image: postgres
      networks:
        - backend

    vote:
      image: voting-app
      ports:
        - "5000:80"
      networks:
        - frontend
        - backend

    results:
      image: results-app
      ports:
        - "5001:80"
      networks:
        - frontend
        - backend

    worker:
      image: worker
      networks:
        - backend

  networks:
    frontend:
    backend:
  ```
  - `networks` ở root: Định nghĩa mạng.
  - `networks` dưới service: Gán mạng cho container.
