# Ghi chú học tập: Lệnh, Đối số và Điểm vào trong Docker

## Bài giảng: Lệnh, Đối số và Điểm vào (Commands, Arguments, Entry Points) trong Docker

### Mục tiêu
- Hiểu cách Docker chạy container từ image và lý do container dừng ngay sau khi khởi chạy.
- Nắm rõ cách sử dụng lệnh `CMD` và `ENTRYPOINT` trong Dockerfile để xác định chương trình chạy trong container.
- Phân biệt cách truyền đối số và thay đổi hành vi container khi khởi chạy.

### 1. Tổng quan về cách container hoạt động
- **Khác biệt với máy ảo (Virtual Machine)**:
  - Container không nhằm mục đích chạy toàn bộ hệ điều hành như máy ảo.
  - Container được thiết kế để chạy một tác vụ hoặc quy trình cụ thể (specific task/process), ví dụ:
    - Chạy máy chủ web (web server).
    - Chạy máy chủ ứng dụng (application server).
    - Chạy cơ sở dữ liệu (database).
    - Thực hiện tính toán hoặc phân tích (computation/analysis tasks).
  - Container chỉ tồn tại khi quy trình bên trong nó còn hoạt động. Nếu quy trình dừng hoặc gặp sự cố, container sẽ thoát (exits).

- **Ví dụ với image Ubuntu**:
  - Khi chạy lệnh `docker run ubuntu`, container được tạo từ image Ubuntu sẽ khởi chạy và thoát ngay lập tức.
  - Lý do: Image Ubuntu sử dụng `bash` làm lệnh mặc định (`CMD ["bash"]` trong Dockerfile).
  - `bash` là một shell, cần terminal để nhận đầu vào. Nếu không có terminal (mặc định Docker không gắn terminal), `bash` thoát ngay, dẫn đến container cũng thoát.

- **Kiểm tra trạng thái container**:
  - Lệnh `docker ps`: Chỉ liệt kê các container đang chạy (sẽ không thấy container Ubuntu).
  - Lệnh `docker ps -a`: Liệt kê tất cả container, kể cả đã thoát (sẽ thấy container Ubuntu ở trạng thái `exited`).

### 2. Lệnh `CMD` trong Dockerfile
- **Ý nghĩa**:
  - Lệnh `CMD` (Command) xác định chương trình mặc định sẽ chạy khi container khởi động.
  - Ví dụ:
    - Trong image Nginx, `CMD` chạy lệnh `nginx`.
    - Trong image MySQL, `CMD` chạy lệnh `mysql`.

- **Định dạng**:
  - **Shell form**: `CMD command param1 param2` (chạy lệnh trong shell, ví dụ: `CMD sleep 5`).
  - **Exec form (JSON array)**: `CMD ["executable", "param1", "param2"]` (chạy trực tiếp chương trình, không qua shell, ví dụ: `CMD ["sleep", "5"]`).
    - Lưu ý: Trong exec form, phần tử đầu tiên phải là chương trình thực thi (executable).

- **Ví dụ với image Ubuntu**:
  - Dockerfile của Ubuntu sử dụng `CMD ["bash"]`.
  - Khi chạy `docker run ubuntu`, container khởi chạy `bash` nhưng thoát ngay vì không có terminal.

- **Thay đổi lệnh mặc định khi chạy container**:
  - Có thể ghi đè lệnh mặc định bằng cách thêm lệnh vào `docker run`.
  - Ví dụ: `docker run ubuntu sleep 5`
    - Container chạy lệnh `sleep 5`, đợi 5 giây, rồi thoát.

### 3. Tùy chỉnh lệnh mặc định trong image
- **Tạo image mới**:
  - Để thay đổi lệnh mặc định vĩnh viễn, tạo image mới từ image cơ sở (base image) và sửa `CMD`.
  - Ví dụ Dockerfile:
    ```dockerfile
    FROM ubuntu
    CMD ["sleep", "5"]
    ```
  - Xây dựng image: `docker build -t ubuntu-sleeper .`
  - Chạy container: `docker run ubuntu-sleeper` (container sẽ ngủ 5 giây rồi thoát).

- **Vấn đề với giá trị cố định**:
  - Trong ví dụ trên, thời gian ngủ (5 giây) được cố định trong `CMD`.
  - Để thay đổi (ví dụ, ngủ 10 giây), phải chạy `docker run ubuntu-sleeper sleep 10`, nhưng điều này ghi đè toàn bộ lệnh `CMD`.

### 4. Sử dụng `ENTRYPOINT` để linh hoạt hơn
- **Ý nghĩa**:
  - Lệnh `ENTRYPOINT` xác định chương trình chính chạy khi container khởi động.
  - Các tham số truyền qua dòng lệnh (command line) sẽ được **nối thêm** (appended) vào `ENTRYPOINT`, không ghi đè như `CMD`.

- **Ví dụ với `ENTRYPOINT`**:
  - Dockerfile:
    ```dockerfile
    FROM ubuntu
    ENTRYPOINT ["sleep"]
    ```
  - Chạy container: `docker run ubuntu-sleeper 10`
    - Kết quả: Container chạy lệnh `sleep 10`.

- **So sánh `CMD` và `ENTRYPOINT`**:
  - Với `CMD`: Các tham số dòng lệnh **thay thế toàn bộ** lệnh `CMD`.
  - Với `ENTRYPOINT`: Các tham số dòng lệnh được **nối thêm** vào `ENTRYPOINT`.

- **Lỗi khi thiếu tham số**:
  - Nếu chạy `docker run ubuntu-sleeper` mà không cung cấp số giây, lệnh sẽ là `sleep` (thiếu đối số), dẫn đến lỗi: `sleep: missing operand`.

### 5. Kết hợp `ENTRYPOINT` và `CMD` để cung cấp giá trị mặc định
- **Cách hoạt động**:
  - Sử dụng `ENTRYPOINT` để xác định chương trình chính.
  - Sử dụng `CMD` để cung cấp tham số mặc định, sẽ được nối vào `ENTRYPOINT` nếu không có tham số nào được truyền qua dòng lệnh.

- **Ví dụ**:
  - Dockerfile:
    ```dockerfile
    FROM ubuntu
    ENTRYPOINT ["sleep"]
    CMD ["5"]
    ```
  - Chạy container:
    - `docker run ubuntu-sleeper`: Chạy `sleep 5` (dùng giá trị mặc định từ `CMD`).
    - `docker run ubuntu-sleeper 10`: Chạy `sleep 10` (ghi đè `CMD`).

- **Lưu ý**:
  - Cả `ENTRYPOINT` và `CMD` nên dùng định dạng JSON (`["command", "param"]`) để đảm bảo tính chính xác khi nối tham số.

### 6. Ghi đè `ENTRYPOINT` khi chạy container
- **Cách thực hiện**:
  - Sử dụng tùy chọn `--entrypoint` trong lệnh `docker run` để thay đổi chương trình chính.
  - Ví dụ: `docker run --entrypoint sleep2.0 ubuntu-sleeper 10`
    - Container chạy lệnh `sleep2.0 10` thay vì `sleep 10`.

### 7. Ghi chú thêm
- **Tóm tắt sự khác biệt**:
  - `CMD`: Xác định lệnh mặc định, có thể bị ghi đè hoàn toàn bởi tham số dòng lệnh.
  - `ENTRYPOINT`: Xác định chương trình chính, tham số dòng lệnh được nối thêm.
  - Kết hợp `ENTRYPOINT` + `CMD`: Cung cấp chương trình chính và tham số mặc định, linh hoạt khi chạy container.
- **Liên kết nội bộ**:
  - Xem thêm về [[Dockerfile]] để hiểu cấu trúc file.
  - Xem [[Docker run]] để tìm hiểu chi tiết về lệnh chạy container.
  - Tham khảo [[Container Lifecycle]] để hiểu vòng đời container.

### 8. Ví dụ thực tế
- **Tạo image tùy chỉnh với `ENTRYPOINT` và `CMD`**:
  ```dockerfile
  FROM ubuntu
  ENTRYPOINT ["sleep"]
  CMD ["5"]
  ```
- **Xây dựng và chạy**:
  ```bash
  docker build -t ubuntu-sleeper .
  docker run ubuntu-sleeper  # Ngủ 5 giây (mặc định)
  docker run ubuntu-sleeper 10  # Ngủ 10 giây
  docker run --entrypoint echo ubuntu-sleeper Hello  # In "Hello"
  ```
