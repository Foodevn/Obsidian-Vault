## Quy tắc 2: Loại bỏ các hằng số (Remove Constants)

### Bản chất của Quy tắc 2

Khi phân tích độ phức tạp [[Big O]], chúng ta không quan tâm đến các chi tiết nhỏ lẻ hoặc các hằng số (constants). Khi dữ liệu đầu vào ($n$) tiến tới một triệu, một tỷ hay vô cực, các phép cộng thêm hay chia nhỏ hằng số gần như không tạo ra sự khác biệt đáng kể nào về mặt **[[Khả năng mở rộng]]** (Scalability).

Do đó, để đơn giản hóa, chúng ta sẽ **lược bỏ tất cả các hằng số**.

### Ví dụ 1: Hàm chứa nhiều hằng số rườm rà

Hãy xem xét một hàm được thiết kế cố tình phức tạp để minh họa: in phần tử đầu tiên, in một nửa mảng, và in chữ 'hi' 100 lần.

```JavaScript
function printFirstItemThenFirstHalfThenSayHi100Times(items) {
  // In phần tử đầu tiên -> Chạy 1 lần
  console.log(items[0]); // O(1)

  // In một nửa số phần tử của mảng -> Chạy n/2 lần
  let middleIndex = Math.floor(items.length / 2);
  let index = 0;
  while (index < middleIndex) {
    console.log(items[index]);
    index++;
  } // O(n/2)

  // In chữ 'hi' 100 lần -> Chạy 100 lần
  for (let i = 0; i < 100; i++) {
    console.log('hi');
  } // O(100)
}
```

**Phân tích và Rút gọn:**

1. **Tính toán thô:** Tổng số phép toán là `O(1 + n/2 + 100)` $\rightarrow$ `O(n/2 + 101)`.
2. **Áp dụng Quy tắc 2:** - Khi $n$ càng lớn, việc cộng thêm `101` bước là hoàn toàn vô nghĩa $\rightarrow$ Bỏ `101`.
    - Việc chia $n$ cho `2` cũng không làm thay đổi bản chất cốt lõi của sự gia tăng $\rightarrow$ Bỏ phép chia `2`.
3. **Kết quả:** Hàm này đơn giản được gọi là **[[O(n)]]**.

### Ví dụ 2: Hàm có nhiều vòng lặp độc lập

Hãy xem xét một hàm có 2 vòng lặp `for` chạy nối tiếp nhau (không lồng nhau):
```JavaScript
function compressBoxesTwice(boxes) {
  // Vòng lặp thứ nhất
  for (let i = 0; i < boxes.length; i++) {
    console.log(boxes[i]);
  } // O(n)

  // Vòng lặp thứ hai
  for (let j = 0; j < boxes.length; j++) {
    console.log(boxes[j]);
  } // O(n)
}
```

**Phân tích và Rút gọn:**

- **Tính toán thô:** `O(n) + O(n)` $\rightarrow$ `O(2n)`.
- **Áp dụng Quy tắc 2:** Bỏ hằng số `2` đứng trước $n$.
- **Kết quả:** Hàm này vẫn là **[[O(n)]]**.

### Cốt lõi cần nhớ

- Dù đồ thị của `O(2n)` có dốc (steep) hơn `O(n)` rất nhiều vì nó phải thực hiện gấp đôi số phép toán, nhưng quỹ đạo và hình dáng của đường biểu diễn **vẫn là một đường thẳng (tuyến tính)**.
- Big O không quan tâm đến độ dốc cụ thể, nó chỉ quan tâm đến _xu hướng gia tăng_ của đường biểu diễn khi đầu vào lớn lên.
- Bạn sẽ **rất hiếm khi** thấy các con số trong ký hiệu Big O thực tế (chẳng hạn không bao giờ có `O(3n)` hay `O(n + 50)`). Các con số thường chỉ xuất hiện trong các chuẩn như **[[O(1)]]**, **O(n^2)**, hoặc **O(2^n)**.
